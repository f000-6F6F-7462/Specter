# HTTP API reference

The API is how the application server *asks for or changes* something. What *happens* arrives over
[NATS](nats-events.md). For a guided walkthrough with code, use the
[App integration guide](app-integration-guide.md).

- **Base URL:** `http://127.0.0.1:8000` (the port is `api.port` in the settings).
- **Machine-readable spec:** `GET /openapi.json` (interactive: `/docs`, `/redoc`). It is generated
  from the code and needs no token, which is fine because the API listens on localhost only. **Use it
  to generate your client types** rather than copying the shapes below by hand. The same document is
  committed as [`contracts/openapi.json`](../../contracts/openapi.json), so types can be generated
  without a running device. The WebSocket endpoint is the one thing it does not describe.
- **Format:** JSON in and out, except where a section says otherwise. Field names are
  `snake_case`. Timestamps are RFC 3339.

## Authentication

Every endpoint except `GET /health` needs the service token as a bearer token:

```http
Authorization: Bearer <token>
```

The token is one long random string in a file (`security.api_token_file`, `/etc/specter/api.token`
by default). In Docker it is `deploy/secrets/api.token` on the device, created by
`make api-token-file` (`make up` runs it) and mounted into the `api` container as a Compose secret;
mount the same file read-only into the application server. `make api-token` prints it. When run
from source it is `.dev/secrets/api.token`, which Specter **creates on first start**, readable only
by its owner. Read it once at startup, from the application server's configuration;
never send it to a browser.

The token identifies *your application*, not a user. Any request that carries it may act on **any
owner**, so keeping users apart is the application server's job. See
[owners](app-integration-guide.md#owners-and-isolation).

## Conventions

**IDs** are generated by Specter: a lowercase prefix and 32 hex characters (`camera_9c1e…`,
`watchlist_…`, `target_…`, `image_…`, `zone_…`, `rule_…`). Treat them as opaque strings.

**Owners.** Almost every path starts with `/owners/{owner_id}`. There is no "create owner" call: an
owner exists as soon as something is created under that id. Entities of another owner behave as if
they did not exist (`404`).

**Partial updates.** `PATCH` bodies contain only the fields to change; omitted fields keep their
value. Unknown fields are **rejected** (`422`), so a typo fails loudly.

**Coordinates** are fractions of the frame, `x` and `y` from `0` to `1`, origin at the top-left.

**Status codes**

| Code | Meaning | Body |
|---|---|---|
| `200` | OK | The entity, or a list |
| `201` | Created | The new entity (or list of entities) |
| `204` | Deleted | Empty. Deleting is safe to repeat only for `DELETE /owners/{owner}`; other deletes return `404` the second time. |
| `401` | Missing or wrong token | `{"detail": "..."}` |
| `404` | Does not exist, **or belongs to another owner** | `{"detail": "..."}` |
| `409` | The camera is not running (live video only) | `{"detail": "..."}` |
| `422` | The request breaks a rule (bad field, unknown field, disabled camera cannot start, …) | `{"detail": "..."}`, or `{"detail": [ … ]}` with one item per field for a schema error |
| `503` | A service Specter needs (Qdrant, go2rtc) is unreachable | `{"detail": "..."}`. Retry later. |

A `404` for another owner's entity is deliberate: it does not reveal that the id exists.

## Endpoints

Paths are relative to the base URL. `{owner}` is `{owner_id}`.

### Operations

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/health` | No token. `200` with `{"status":"ok","version":"…","is_nats_connected":true}`, or `503` with `"degraded"` while NATS is unreachable. |
| `DELETE` | `/owners/{owner}` | Delete **all** of an owner's data: cameras, watchlists, targets, images, alerts, evidence. Idempotent. |

### Cameras

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/owners/{owner}/cameras` | Create a camera. It stays **stopped** until started. `201`. |
| `GET` | `/owners/{owner}/cameras` | List the owner's cameras, oldest first. |
| `GET` | `/owners/{owner}/cameras/{camera}` | One camera. |
| `PATCH` | `/owners/{owner}/cameras/{camera}` | Change fields. A running camera **restarts** with the new settings, unless only `metadata` changed. |
| `DELETE` | `/owners/{owner}/cameras/{camera}` | Delete the camera with its zones and rules. Its alerts stay. `204`. |
| `POST` | `/owners/{owner}/cameras/{camera}/start` | Ask the camera manager to run it. `422` if the camera is disabled. |
| `POST` | `/owners/{owner}/cameras/{camera}/stop` | Ask the camera manager to stop it. |

Create body:

```json
{
  "name": "Front door",
  "source_url": "rtsp://192.168.1.20:554/stream1",
  "credentials": { "username": "admin", "password": "…" },
  "watchlist_ids": ["watchlist_…"],
  "detection_classes": ["person"],
  "sampling": { "mode": "adaptive", "target_fps": 10, "minimum_fps": 3, "is_motion_gating_enabled": true },
  "is_enabled": true,
  "metadata": { "location": "Lobby" }
}
```

Only `name` and `source_url` are required.

| Field | Notes |
|---|---|
| `source_url` | Must **not** contain a password (`422`). Send it as `credentials`. |
| `credentials` | Stored encrypted. In `PATCH`, send `"credentials": null` to remove them. |
| `watchlist_ids` | The watchlists this camera identifies people against. All must belong to the owner. |
| `detection_classes` | COCO class names such as `person`, `car`, `dog`. **Empty means every class.** |
| `sampling.mode` | `adaptive` (slows down when the detector is busy, never below `minimum_fps`) or `fixed`. |
| `is_enabled` | A disabled camera cannot be started. |
| `metadata` | Free-form JSON object that Specter stores and returns untouched. `PATCH` replaces it whole, and never restarts the camera. |

Response:

```json
{
  "id": "camera_…", "owner_id": "acme", "name": "Front door",
  "source_url": "rtsp://192.168.1.20:554/stream1",
  "username": "admin", "has_password": true,
  "watchlist_ids": ["watchlist_…"], "detection_classes": ["person"],
  "sampling": { "mode": "adaptive", "target_fps": 10, "minimum_fps": 3, "is_motion_gating_enabled": true },
  "is_enabled": true,
  "desired_state": "stopped",
  "metadata": { "location": "Lobby" },
  "live_status": null
}
```

- The **password is never returned**; `has_password` says whether one is stored.
- `desired_state` (`running` or `stopped`) is *what you asked for*. `live_status` (`starting`,
  `running`, `reconnecting`, `stopped`, `failed`, or `null`) is *what the camera process reports*.
  `null` means no process is reporting right now. It is also `null` if NATS is unreachable.

### Zones

An area of a camera's view, drawn as a polygon.

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/owners/{owner}/cameras/{camera}/zones` | Create. `201`. |
| `GET` | `/owners/{owner}/cameras/{camera}/zones` | List. |
| `GET` | `/owners/{owner}/cameras/{camera}/zones/{zone}` | One zone. |
| `PATCH` | `/owners/{owner}/cameras/{camera}/zones/{zone}` | Change `name` or `polygon`. |
| `DELETE` | `/owners/{owner}/cameras/{camera}/zones/{zone}` | Delete. `204`. |

```json
{ "name": "Driveway", "polygon": [ {"x":0.1,"y":0.5}, {"x":0.6,"y":0.5}, {"x":0.6,"y":0.95}, {"x":0.1,"y":0.95} ] }
```

A polygon needs **at least 3 points**.

### Rules

What Specter should alert on, per camera. Two kinds, chosen with `kind`.

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/owners/{owner}/cameras/{camera}/rules` | Create. `201`. |
| `GET` | `/owners/{owner}/cameras/{camera}/rules` | List (zone rules first, then line rules). |
| `GET` | `/owners/{owner}/cameras/{camera}/rules/{rule}` | One rule. |
| `PATCH` | `/owners/{owner}/cameras/{camera}/rules/{rule}` | Change fields. `422` if a field does not apply to the rule's kind. |
| `DELETE` | `/owners/{owner}/cameras/{camera}/rules/{rule}` | Delete. `204`. |

Zone occupancy (fires when an object stays in a zone for `minimum_dwell_seconds`):

```json
{ "kind": "zone_occupancy", "zone_id": "zone_…", "object_classes": ["person"], "minimum_dwell_seconds": 10, "is_enabled": true }
```

Line crossing (fires when an object crosses the line):

```json
{ "kind": "line_crossing", "line_start": {"x":0.2,"y":0.5}, "line_end": {"x":0.8,"y":0.5}, "direction": "either", "object_classes": [], "is_enabled": true }
```

`direction` is `left_to_right`, `right_to_left` or `either`. Empty `object_classes` means every
class. The response contains every field of both kinds, with the ones that do not apply set to
`null`.

### Watchlists

A named group of targets, with the thresholds used to match them.

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/owners/{owner}/watchlists` | Create. `201`. |
| `GET` | `/owners/{owner}/watchlists` | List. |
| `GET` | `/owners/{owner}/watchlists/{watchlist}` | One watchlist. |
| `PATCH` | `/owners/{owner}/watchlists/{watchlist}` | Change fields. Running cameras apply new thresholds **without restarting**. |
| `DELETE` | `/owners/{owner}/watchlists/{watchlist}` | Delete with its targets, images and embeddings. Alerts stay. `204`. |

```json
{ "name": "Banned visitors", "target_type": "person", "kind": "blacklist",
  "face_match_threshold_ratio": 0.45, "appearance_match_threshold_ratio": 0.75, "metadata": {} }
```

| Field | Notes |
|---|---|
| `target_type` | `person`, `vehicle` or `object`. **Cannot be changed** after creation. Required. |
| `kind` | `watchlist` (default) or `blacklist`. A label for your application to interpret; Specter matches both the same way. |
| `*_threshold_ratio` | 0 to 1. Higher means stricter (fewer, surer matches). Defaults `0.45` for faces and `0.75` for appearance. |
| `metadata` | Free-form JSON object that Specter stores and returns untouched. Use it for your own ids. |

### Targets and reference images

A target is a person, vehicle or object to recognize, defined by one or more reference photos. See
[flow 4.2](../architecture.md#42-adding-targets-with-reference-photos) for what happens after upload.

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/owners/{owner}/watchlists/{watchlist}/targets` | Create a **batch** of targets with photos. `multipart/form-data`. `201`. |
| `GET` | `/owners/{owner}/watchlists/{watchlist}/targets` | List. |
| `GET` | `/owners/{owner}/watchlists/{watchlist}/targets/{target}` | One target. |
| `PATCH` | `/owners/{owner}/watchlists/{watchlist}/targets/{target}` | Change `label`, `metadata` or `is_enabled`. A disabled target stops matching at once. |
| `DELETE` | `/owners/{owner}/watchlists/{watchlist}/targets/{target}` | Delete with its images and embeddings. Alerts stay. `204`. |
| `POST` | `/owners/{owner}/watchlists/{watchlist}/targets/{target}/images` | Add photos to a target. `multipart/form-data`. `201`. |
| `GET` | `/owners/{owner}/watchlists/{watchlist}/targets/{target}/images/{image}` | The uploaded photo, with its original content type. |
| `DELETE` | `/owners/{owner}/watchlists/{watchlist}/targets/{target}/images/{image}` | Remove one photo. `204`. |
| `GET` | `/owners/{owner}/enrollment-batches/{batch}` | The targets created together, to follow their enrollment. |

**Creating a batch** is `multipart/form-data` with two kinds of part:

| Part | Content |
|---|---|
| `targets` | A **JSON string**: a list of `{ "label": "…", "metadata": {…}, "image_file_names": ["a.jpg", …] }` |
| `images` | One file part per photo, repeated. The part's **file name** must match a name in `image_file_names`. |

Rules, all checked before anything is stored (`422` otherwise, and nothing is saved):

- every uploaded file is named by **exactly one** target, and every named file is uploaded;
- file names are unique within the request;
- content type is `image/jpeg`, `image/png` or `image/webp`;
- a file is at most `api.maximum_image_size_mebibytes` (10 MiB by default);
- the list has at least one target.

`POST …/images` takes only the `images` parts (no `targets`).

```bash
curl -X POST "$BASE/owners/acme/watchlists/$WL/targets" \
  -H "Authorization: Bearer $TOKEN" \
  -F 'targets=[{"label":"Jane","metadata":{"crm_id":"42"},"image_file_names":["jane1.jpg","jane2.jpg"]}]' \
  -F 'images=@jane1.jpg;type=image/jpeg' \
  -F 'images=@jane2.jpg;type=image/jpeg'
```

Target response:

```json
{
  "id": "target_…", "watchlist_id": "watchlist_…", "label": "Jane", "target_type": "person",
  "is_enabled": true, "metadata": {"crm_id": "42"},
  "enrollment_batch_id": "enrollment_batch_…",
  "enrollment_status": "queued",
  "reference_images": [
    { "id": "image_…",
      "embeddings": [
        { "modality": "face", "status": "pending", "rejection_reason": null, "quality_score_ratio": null },
        { "modality": "appearance", "status": "pending", "rejection_reason": null, "quality_score_ratio": null }
      ] }
  ]
}
```

| `enrollment_status` | Meaning |
|---|---|
| `queued` | Nothing is processed yet. |
| `partial` | Some embeddings are done, some are not. |
| `ready` | The target can be matched. |
| `failed` | No embedding was usable. Look at each `rejection_reason`, and ask for better photos. |

Per embedding, `status` is `pending`, `embedded` or `rejected`. The `201` **does not mean the photo
is usable**: the detector still has to find a face. Follow the batch with
`GET …/enrollment-batches/{batch}` or the [`enrollment.status_changed`](nats-events.md#enrollmentstatuschanged)
event. Rejection reasons are listed there.

### Alerts

Alerts are created by Specter, never by the application. There are two kinds, stored separately:
**identity matches** (a target was recognized) and **rule alerts** (a rule fired).

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/owners/{owner}/alerts` | One page of alerts of both kinds (or of one, with `kind`), newest first. |
| `GET` | `/owners/{owner}/alerts/summary` | Totals by kind and review state, and per UTC day. |
| `GET` | `/owners/{owner}/alerts/identity-matches` | One page of identity-match alerts, newest first. |
| `GET` | `/owners/{owner}/alerts/rules` | One page of rule alerts, newest first. |
| `GET` | `/owners/{owner}/alerts/{alert}` | One alert of either kind. |
| `POST` | `/owners/{owner}/alerts/{alert}/acknowledge` | Mark as seen, without a verdict. |
| `POST` | `/owners/{owner}/alerts/{alert}/resolve` | Record the verdict. Also acknowledges. |
| `GET` | `/owners/{owner}/alerts/{alert}/snapshot` | The frame the alert was raised on, `image/jpeg`. |

**Listing** takes these query parameters, all optional:

| Parameter | Meaning |
|---|---|
| `camera_id` | Only these cameras' alerts. Repeat it for several cameras: `?camera_id=camera_a&camera_id=camera_b`. |
| `kind` | `identity_match` or `rule`. Only on `GET /alerts`. |
| `disposition` | `unreviewed`, `true_positive` or `false_positive`. |
| `created_since`, `created_until` | Time window. RFC 3339 **with a time zone**, for example `2026-09-20T00:00:00Z`. |
| `limit` | 1 to 200, default 50. |
| `cursor` | The `next_cursor` of the previous page. |

Response: `{ "alerts": [ … ], "next_cursor": "…" | null }`. **Page by cursor**: pass `next_cursor`
back as `cursor` to get the next, older page, and stop when it is `null`. The cursor is opaque;
do not build or parse it. New alerts arriving between requests never shift a page.

An alert (fields of the other kind are `null`):

```json
{
  "id": "message_9f1c…", "kind": "identity_match", "owner_id": "acme", "camera_id": "camera_…",
  "track_id": 17, "object_class": "person",
  "bounding_box": { "x": 0.41, "y": 0.22, "width": 0.12, "height": 0.38 },
  "frame_captured_at": "2026-09-20T12:00:00Z", "created_at": "2026-09-20T12:00:00Z",
  "has_snapshot": true,
  "review": { "disposition": "unreviewed", "is_acknowledged": false, "note": null },
  "watchlist_id": "watchlist_…", "target_id": "target_…", "modality": "face",
  "similarity_ratio": 0.62, "margin_ratio": 0.11,
  "rule_id": null, "rule_kind": null, "zone_id": null, "dwell_seconds": null, "crossing_direction": null
}
```

- **`id` equals the `message_id` of the NATS event that announced it.** That links a live
  notification to its stored alert.
- `kind` is `identity_match` or `rule`.
- `has_snapshot: false` (or a `404` from `/snapshot`) means the image could not be saved, or the
  retention limit (30 days or 5 GiB by default) already removed it.

**Resolving** takes `{ "disposition": "true_positive" | "false_positive", "note": "optional text" }`
and returns the updated alert. Only these two values are accepted.

**The summary** takes `camera_id` (repeatable), `created_since` and `created_until`, and returns:

```json
{
  "total_count": 12, "unacknowledged_count": 5,
  "counts": [ { "kind": "identity_match", "disposition": "unreviewed", "is_acknowledged": false, "count": 5 } ],
  "daily_counts": [ { "day": "2026-09-20", "kind": "identity_match", "count": 7 } ]
}
```

`counts` and `daily_counts` list only the combinations that occur; `daily_counts` is oldest first.

### Live video

Only for cameras that have been **started** (`desired_state` is `running`); otherwise `409`. A
started camera whose process is still connecting can pass this check and then fail with `503`. All under
`/owners/{owner}/cameras/{camera}/live`. Details and when to use which:
[Live video](live-video.md).

| Method | Path | Returns |
|---|---|---|
| `GET` | `/frame.jpeg` | The latest frame, `image/jpeg`. |
| `GET` | `/stream.m3u8` | HLS playlist. |
| `GET` | `/hls/{file}` | HLS segments the playlist links to. |
| `POST` | `/webrtc` | WebRTC negotiation: body is an SDP offer (`application/sdp`), reply is the SDP answer. |
| `WS` | `/mse` | Low-delay MSE stream over a WebSocket. **Not in `openapi.json`.** |

## Errors in practice

- **`404` right after an alert event** is normal for a moment: the event is published first and the
  alert is recorded a moment later. Retry after a short delay.
- **`422` has two shapes.** A rule of Specter's own (`"a disabled camera cannot be started"`) gives
  `{"detail": "text"}`; a schema mistake gives `{"detail": [ {"loc": […], "msg": "…"} ]}`. Handle both.
- **`503` is transient.** Retry with backoff. A change to the vector index is applied *before* the
  database change, so a failed request leaves the target matching exactly as before.
- **A camera create or start that returns `2xx` has only been *accepted*.** Confirm the camera is up
  through `status_changed` or `live_status`.
